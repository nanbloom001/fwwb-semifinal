# 2026-05-25 Track 训练当日优先级记录

## 今日目标

今天只聚焦两个方向：

1. 优化地形门控。
2. 优化迷宫导航效果。

## 当前判断

迷宫导航已经暴露为当前 Track 方案里的主要风险点。后续不要把注意力分散到过多 reward 或速度策略上，除非这些改动能直接服务于：

- 更可靠地区分平地、缓坡、台阶、墙体/迷宫障碍。
- 更可靠地判断低/中/高难度门控是否真的生效。
- 提升迷宫段的转向、避墙、绕行和到达出口能力。

## 已确认的约束

- 之前测试已经表明，仅在 `agent_ppo` 侧直接读取 per-env terrain type / terrain level 标签不可靠，不能作为正式门控基础。
- 当前门控优化应优先基于观测几何特征：`height_scanner`、必要时结合 `nav_scanner`。
- 地形门控和难度门控需要先通过 shadow/probe 面板验证，再进入控制或 reward shaping。
- 迷宫优化的第一目标是完成率，不是单纯速度；Track 总分外层受 completion ratio 影响，未完成时速度、姿态、能耗收益都无法转化为有效总分。

## 下一步工作原则

- 先验证门控：current / nan / raw_fused 三套门控的可用性、地形比例、难度比例、分歧率。
- 再处理迷宫：重点看墙体识别、通道开放方向、转向触发、贴墙/撞墙、出口前屏风绕行。
- 每次只让一个机制进入控制链路；其他候选机制先 shadow 观测，避免训练结果无法归因。
- 长训前必须确认监控面板中关键门控指标不是空值、不是 reward 权重稀释后的假数值。
